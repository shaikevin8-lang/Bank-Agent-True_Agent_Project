# 前端模型接入配置 · 接口契约（冻结版 v2）

> 本文件是「前端页面直接填写 Base URL 与 API Key」功能的**唯一接口契约**。
> 后端（`web_test/server.py`）、运行时配置（`common/runtime_config.py`、
> `common/model_manager.py`）、前端（`web_test/index.html`）、测试（`tests/`）
> 均以本文件为准；任何一方需要变更字段，先改本文件。

> **v2 相对 v1 的变更（一句话版）**：删除「供应商预设」下拉、`PROVIDER_PRESETS` 表、
> `ModelConfigManager.presets()` 与 `GET /api/settings/llm/presets`（该路径现为 404），
> 删除「高级参数」折叠块（温度 / 最大 token 数）；新增 `response_format`（响应格式，
> 默认 `text`），并把 `timeout` 提升为常显字段。其余接口、错误码、安全约束均不变。

## 1. 背景与目标

改造前：模型接入信息只能来自环境变量（`Deepseek_API` / `Tavily_API`）与代码内写死的
`base_url`（`https://api.deepseek.com`），无法在页面更换接入端点。

改造后：页面提供**纯手填**的接入表单 —— **Base URL**、**API Key**、**模型名**，
外加 **响应格式** 与 **超时** 两个请求参数，点击「测试连接」校验、点击「保存并启用」
即时生效，**无需重启服务、无需改环境变量**。密钥仅保存在进程内存，
**绝不落盘、绝不回传前端明文**。

> 页面**不再**提供「供应商预设」下拉：用户直接从服务商文档复制 Base URL 与模型名填入即可。
> 各家的 Base URL / 模型名取值参考见 [供应商接入预置调研.md](供应商接入预置调研.md)
> ——该文档仅作**手填参考**保留，预置功能已在 v2 移除。

## 2. 术语与模式（mode）

| mode | 含义 | 触发条件 |
| --- | --- | --- |
| `model` | 使用运行时页面配置的模型 | 页面「保存并启用」成功后 |
| `env` | 使用环境变量中的模型配置 | 未做页面配置，但存在 `Deepseek_API`（或 `DEEPSEEK_API` / `DEEPSEEK_API_KEY`） |
| `mock` | 离线 Mock 模式（固定话术，可演示不可真答） | 既无页面配置也无环境变量 |
| `unconfigured` | 同上，用于搜索服务未配置时的表述 | 仅搜索服务使用 |

`source` 取值：`runtime`（页面配置）/ `env`（环境变量）/ `none`。

## 3. 统一响应包（所有 `/api/settings/*` 接口）

成功（HTTP 200）：

```json
{ "ok": true, "message": "", "error_code": null, "data": { } }
```

失败（HTTP 400 / 422 / 502）：

```json
{ "ok": false, "message": "无法连接模型服务：请检查 Base URL 与网络", "error_code": "LLM_CONNECTION_FAILED", "data": null }
```

`error_code` 取值表：

| error_code | HTTP | 含义 |
| --- | --- | --- |
| `LLM_CONFIG_INVALID` | 422 | 字段格式不合法（URL 非法、模型名为空、数值越界、响应格式不在白名单等） |
| `LLM_KEY_REQUIRED` | 422 | 当前既无运行时 Key 也无环境变量 Key，且请求未提供 Key |
| `LLM_AUTH_FAILED` | 502 | 鉴权失败（401/403，Key 无效或无权限） |
| `LLM_MODEL_NOT_FOUND` | 502 | 模型名不存在（404 或上游明确报 model not found） |
| `LLM_RATE_LIMITED` | 502 | 触发限流（429） |
| `LLM_TIMEOUT` | 502 | 请求超时 |
| `LLM_CONNECTION_FAILED` | 502 | 网络/域名/端口不可达 |
| `LLM_REQUEST_FAILED` | 502 | 其它上游错误（含响应结构不符合 OpenAI 兼容格式） |
| `SEARCH_CONFIG_INVALID` | 422 | 搜索配置字段非法 |
| `SEARCH_KEY_REQUIRED` | 422 | 搜索 Key 缺失 |
| `SEARCH_AUTH_FAILED` | 502 | 搜索鉴权失败 |
| `SEARCH_CONNECTION_FAILED` | 502 | 搜索网络失败 |

**关键约束**：任何响应体（含错误详情、日志）中**不得出现完整 API Key**；
只允许出现 `api_key_masked`，格式为 `前3位 + "..." + 后4位`；
长度不足 8 位时全部替换为 `*`（实现在 `common/runtime_config.py` 的 `mask_secret`）。

**错误文本擦除**：部分网关会在错误信息里原样回显收到的 Key
（例如 `Invalid key supplied: sk-xxx`），而错误消息与 `trace.error_detail` 都会回到前端。
因此所有面向用户/前端的错误文本在生成前都会经
`common/model_manager.py` 的 `redact_secrets` 擦除当前生效的密钥
（命中处替换为 `***`）。对应测试：`tests/test_model_manager.py` 中的
`test_upstream_error_echoing_the_key_is_scrubbed`、
`test_configure_failure_scrubs_the_key_too`、
`test_chat_failure_reply_scrubs_the_key`。

## 4. 模型配置对象（snapshot）

```json
{
  "configured": true,
  "mode": "model",
  "source": "runtime",
  "base_url": "https://api.deepseek.com/v1",
  "model": "deepseek-flash",
  "response_format": "text",
  "temperature": 0.0,
  "max_tokens": 1024,
  "timeout": 120.0,
  "api_key_configured": true,
  "api_key_masked": "sk-...1234",
  "env_api_key_present": false,
  "updated_at": "2026-01-01T00:00:00+00:00",
  "active_model_class": "DeepSeekChat"
}
```

字段说明：

- `configured`：`mode` 为 `model` 或 `env` 时为 `true`。
- `response_format`：当前生效的响应格式，取值 `text` / `json_object` / `json_schema`，
  默认 `text`（含义见第 6.1 节）。
- `temperature` / `max_tokens`：**legacy 兼容字段**，仍出现在 snapshot 中，也仍可按
  第 6.1 节的规则通过 curl/API 传入，但页面已不再展示、也不再发送它们。
- `timeout`：请求超时秒数；**未配置时快照返回 `0.0`**（表示「未设置」），
  配置后为实际值。页面把 `0.0` 视为「留空」，由后端套用默认 `120.0`；
  v2 起为页面常显字段。
- `active_model_class`：当前实际生效的模型实现类名（`DeepSeekChat` / `MockChat`），便于前端展示与排障。
- `updated_at`：最近一次运行时配置成功的 UTC ISO8601 时间；无则为 `null`。

## 6. 接口清单

### 6.1 模型配置

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/settings/llm` | 读取当前模型配置 snapshot（第 4 节） |
| `PUT` | `/api/settings/llm` | 保存并启用（**先探测成功才替换**，失败保持原配置不变） |
| `POST` | `/api/settings/llm/test` | 仅测试连接，不改变当前生效配置 |
| `DELETE` | `/api/settings/llm` | 清除运行时配置，回落到环境变量；若环境变量也没有则回落到 `mock` |

> v2 已删除 `GET /api/settings/llm/presets`（供应商预置列表）：该路径**不再存在**，
> 访问会返回 HTTP 404。若你的脚本/收藏夹里还有它，请直接删掉。

`PUT` / `POST /test` 请求体：

```json
{
  "base_url": "https://api.deepseek.com/v1",
  "api_key": "sk-xxxxxxxx",
  "model": "deepseek-chat",
  "response_format": "text",
  "timeout": 120.0
}
```

- `api_key` 允许为 `null` / 省略 / 空串 → 表示**沿用当前已配置的 Key**（运行时优先，其次环境变量）；
  若两者都没有 → `LLM_KEY_REQUIRED`。
- `base_url` 必填，必须是 `http://` 或 `https://` 开头的绝对地址，长度 ≤ 2048。
  规范化规则（实现见 `common/runtime_config.py` 的 `normalize_base_url`，**幂等**）：
  1. 去首尾空白；
  2. 拒绝内嵌凭据（`https://user:pass@host`）——凭据会随 `base_url` 回传前端并进入日志；
  3. 拒绝带 `?query` 或 `#fragment` 的地址；
  4. 折叠路径中的 `//` 与 `..`；
  5. 剥掉误粘贴的端点后缀 `/chat/completions`（[OI] SDK 会自行追加该路径）；
  6. 去尾部 `/`；路径为空或为 `/` 时补 `/v1`；已带路径（如 `/v1`、`/openai/v1`、
     `/compatible-mode/v1`）原样保留。
- `model` 必填，长度 1~200。
- `response_format` **可选**，映射到 [OI] 的 `response_format` 请求参数：
  - 省略 / `null` / 空串 ⇒ 按 `text` 处理；实现会先去首尾空白并转小写再比对；
  - 合法值**仅三个**：`text`、`json_object`、`json_schema`；
  - 取值在这三个之外 ⇒ HTTP 422 `LLM_CONFIG_INVALID`，message 固定为
    `响应格式只支持 text / json_object / json_schema`；
  - `text`（默认）：**不额外发送任何内容**，请求体与 v1 完全一致，行为不变；
  - `json_object`：透传 `{"type": "json_object"}`；
  - `json_schema`：透传
    `{"type": "json_schema", "json_schema": {"name": "bank_agent_response", "strict": false, "schema": {"type": "object", "additionalProperties": true}}}`。
    这里**刻意使用宽松 schema**（`{"type": "object", "additionalProperties": true}` + `strict: false`），
    只要求「返回一个 JSON 对象」，以免与 Agent 自身的工具调用契约互相打架。
- `timeout` 缺省 `120.0`，范围 `1.0 ~ 300.0`（秒）。v2 起为页面常显字段（不再藏在折叠块里）。
  缺省值依据见 `docs/排障-模型接入404与旧进程.md` 的「模型调用失败 Request timed out」一节：
  实测上游首字节常态 1.3~5.8 秒、多轮大 prompt 偶发 32~36 秒，30 秒会把正常抖动变成必然失败。
  该值同时是**唯一**的重试预算——客户端不再叠加 SDK 的隐式重试。
- `temperature` 缺省 `0.0`，范围 `0.0 ~ 2.0`；`max_tokens` 缺省 `1024`，范围 `1 ~ 32768`。
  **两者仍是可选的请求体字段（为 curl/API 用户保留），但页面不再展示也不再发送。**

`POST /api/settings/llm/test` 成功时 `data`：

```json
{ "ok": true, "latency_ms": 812, "model": "deepseek-flash", "reply": "pong" }
```

`POST /test` **无论探测成功还是失败，HTTP 状态码均为 200**，由顶层 `ok` 字段表达结果；
只有请求体本身格式非法时才返回 422 `LLM_CONFIG_INVALID`。

> 请求体校验失败（字段缺失、类型不符等）也走统一响应包，不会返回 FastAPI 默认的
> `{"detail": [...]}`：服务端注册了 `RequestValidationError` 处理器，统一渲染为
> `{"ok": false, "message": "请求参数不合法：base_url", "error_code": "LLM_CONFIG_INVALID", "data": null}`。

### 6.2 搜索配置

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/settings/search` | 读取搜索配置 snapshot（第 5 节） |
| `PUT` | `/api/settings/search` | 保存并启用（先探测成功才替换） |
| `POST` | `/api/settings/search/test` | 仅测试连接 |
| `DELETE` | `/api/settings/search` | 清除运行时配置，回落环境变量 |

请求体：

```json
{
  "base_url": "https://api.tavily.com/search",
  "api_key": "tvly-xxxxxxxx",
  "max_results": 5,
  "timeout": 10.0
}
```

- `base_url` 必填、绝对 http(s) 地址、**不做 `/v1` 补全**（Tavily 是完整端点地址）。
  传了**空字符串**时返回 422 `SEARCH_CONFIG_INVALID`，不会静默回落到 Tavily 默认端点
  （否则用户没填地址，带 Key 的请求却会发往第三方服务）。
  > 注意区分两种「没填」：字段**整个缺失**属于请求体校验失败，由
  > `web_test/server.py` 的 `RequestValidationError` 处理器统一渲染为 422
  > `LLM_CONFIG_INVALID`（该处理器对所有 `/api/settings/*` 路由共用）；只有
  > 传了空串才走 `build_search_config`，返回 `SEARCH_CONFIG_INVALID`。
  > 页面表单始终会带上该字段，正常点选不会遇到这个差别。
- `max_results` 缺省 `5`，范围 `1 ~ 20`。
- `timeout` 缺省 `10.0`，范围 `1.0 ~ 120.0`。
- 与模型侧一致，`POST /api/settings/search/test` 探测失败时 **HTTP 状态码也是 200**，
  由顶层 `ok` 字段表达结果；`PUT /api/settings/search` 则按第 3 节错误码表返回 4xx/5xx。
- **这一组接口是可选的**：不配置时 `common/tavily_search.py` 返回
  `{"status": "error", "error": "未配置联网搜索服务：请在页面「模型设置 · 联网搜索」填写接口地址与 API Key，或设置环境变量 Tavily_API"}`，
  通用 Agent 仍会正常作答。

## 7. 安全与工程约束（硬性）

1. **密钥绝不落盘**：不得写入任何文件、不得写入日志、不得写入 `__pycache__` 之外的持久层。
2. **密钥绝不回传明文**：所有接口只回传 `api_key_masked`。
3. **失败不覆盖**：`PUT` 必须先探测成功，探测失败时当前生效配置保持不变。
4. **热切换**：配置变更后，**已构建的 LangGraph 图无需重建**即可使用新模型
   （通过 `RuntimeChatModel` 委托代理实现）。
5. **向后兼容**：未配置页面时行为与改造前完全一致（环境变量优先，否则 Mock 模式）；
   `Example/` 下既有测试与脚本必须继续通过。
6. **不修改参考项目**：`D:\Bank-AI-Agent\bank-agent` 只读，任何文件不得在其中创建或修改。
7. **前端零依赖**：`web_test/index.html` 保持单文件原生 HTML/CSS/JS，不引入构建工具与 CDN 依赖。
8. **无预置表**：v2 起代码与接口中**不存在**供应商预置数据（无 `PROVIDER_PRESETS`、
   无 `presets()`、无 `/api/settings/llm/presets`）。Base URL 与模型名一律由用户手填。

## 8. 前端设置面板交互要求

1. 顶栏齿轮按钮打开「模型接入设置」弹窗；打开时自动 `GET` 模型 snapshot
   （以及搜索 snapshot）回填表单。
2. 弹窗由两部分组成：常显的**模型接入**表单，以及**默认折叠**的
   「联网搜索接入（可选）」`<details>` 区块。
3. 模型接入表单共**五个字段**（`响应格式` 与 `超时（秒）` 在同一行）：
   - `Base URL`：文本输入，必填，手填服务商接口前缀；
   - `API Key`：password 输入，可点「显示」核对；已配置过时留空表示沿用原 Key；
   - `模型名`：文本输入，必填；
   - `响应格式`：`<select>`，**恰好三个选项** —— `文本（推荐）`（值 `text`，**默认选中**）、
     `JSON 对象`（值 `json_object`）、`JSON Schema`（值 `json_schema`）；
   - `超时（秒）`：数字输入，范围 `1 ~ 300`。**留空表示沿用后端默认值 `120`**
     （由 `placeholder="120"` 提示）；未配置状态下后端快照给的 `timeout` 是 `0.0`，
     页面据此把输入框**留空**而不是填 `0`。
   页面**不再有**供应商预设下拉，**也没有**「高级参数」折叠块、温度输入、最大 token 数输入。
4. 弹窗底部**恰好三个按钮**：`清除配置`（左）、`测试连接`、`保存并启用`（右）。
5. 联网搜索区块标题为 `联网搜索接入（可选）`，**默认折叠**；其
   `清除搜索配置` / `测试搜索连接` / `保存搜索配置` 三个按钮放在**区块内部**，
   不占用弹窗底部按钮位——以免用户误以为它是必填项。
6. 状态标签实时展示当前模式。**弹窗头部**徽标文案为
   `模型模式 · <模型名>` / `环境变量模式 · <模型名>` / `未配置模型`；
   **顶栏**徽标与聊天气泡元信息仍用 `模型模式` / `环境变量模式` / `Mock 离线模式`
   （两处文案不同是刻意的：弹窗里说「未配置模型」比「Mock 离线模式」更直白）。
7. 表单校验：Base URL 必填且为 http(s)；模型名必填；未配置过 Key 时 API Key 必填。
8. 错误与成功提示均展示在弹窗内，**不弹 `alert`**。
9. 记住非密钥偏好：`localStorage` 键为 `bank_agent.llm.pref`，**只存**
   `{ base_url, model, response_format }` 三个字段；
   **API Key 绝不写入 `localStorage`**（仅当前页面内存）。
10. 保存成功后，页面聊天气泡的元信息行展示 `模型模式 · 模型名`。
11. 中文界面，与既有页面视觉风格一致（蓝白配色、圆角、`--brand: #2563eb`）。
