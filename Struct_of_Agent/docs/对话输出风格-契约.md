# 对话输出风格契约（纯文本气泡）

本文约定「智能银行助理」**对用户可见文本**的形态：模型可以怎么写，服务端必须
怎么净化，前端只做什么。任何新增 Agent / 接口改动都要满足本文。

---

## 1. 现象与根因

**现象**：聊天气泡里出现满屏 `**粗体**`、`## 小标题`、`|---|---|` 表格、
```` ```json ```` 围栏，甚至整条回复被包成 `{"reply": "……"}`；
多子任务时还会看到 `## 任务1`、`【任务2 · R3】` 这类结构化小标题。

**根因**：

1. **模型侧**：LLM 默认把回复写成 Markdown（甚至按「JSON 输出」习惯包一层外壳），
   它并不知道下游是纯文本渲染。
2. **前端侧**：`web_test/static/js/app.js` 的聊天气泡用
   `element.textContent = ...` + `white-space: pre-wrap` 渲染，**不解析 Markdown**。
   Markdown 源文本因此被逐字符显示出来。
3. **聚合侧**：`SupervisorAgent` 汇总多子任务时，曾用 `## 任务标题` /
   `【任务N · Agent】` 拼装分节回复，把结构化标记直接写进了回复正文。

结论：不能指望模型永远守规矩，必须在**服务端**把回复还原成人类可读的纯文本，
并把「回复是纯文本」固化成一个对外契约。

---

## 2. 两层保障

```
模型输出（可能含 Markdown / JSON）
        │
        ├─ ① 提示词层（软约束）：common/prompts.py → OUTPUT_STYLE_RULE
        │     在 system prompt 里要求「纯文本、不要 Markdown、不要 JSON 外壳」，
        │     降低脏输出的概率，但**不保证**（模型仍会偶发违规）。
        │
        └─ ② 服务端净化层（硬保障）：common/text_format.py
              sanitize_reply(text) -> str     一次性净化（非流式 / 落库 / 单条消息）
              ReplyStreamFilter               有状态流式净化（SSE token 流）
```

### 2.1 净化点清单（缺一不可）

| # | 位置 | 用什么 | 覆盖内容 |
|---|------|--------|----------|
| 1 | 7 个 Agent 出口（`R1`~`R6/agent.py` 的 `chat()`、`common/agent.py` 的 `chat()`） | `sanitize_reply` | 单条子 Agent 回复、审核拦截文案 |
| 2 | `supervisor.py` → `_merge_results()` | `sanitize_reply` | 每个子任务段落；单任务时直接透传、不加前缀 |
| 3 | `supervisor.py` → `chat()` 返回前 | `sanitize_reply` | 最终 `merged["reply"]` 安全网（幂等） |
| 4 | `supervisor.py` → `chat_stream()` | `ReplyStreamFilter`（每子任务一个）+ `sanitize_reply` | 流式 `token` 片段；`task_done` / `done` 事件里的 `result["reply"]` |
| 5 | `supervisor.py` → `_failure_result()` | `sanitize_reply` | 异常兜底文案与 `detail`（错误信息里可能回显网关的 Markdown / JSON） |
| 6 | `web_test/server.py` → `/api/chat` 与 `_record_turn()` | `sanitize_reply` | 返回客户端前、落库前的兜底（防御被替换 / 自定义的 supervisor） |
| 7 | 流式接口 `/api/chat/stream` | **不做净化** | `token` 事件的净化只在 supervisor 层做一次（见 §4.2） |

---

## 3. 对外契约

### 3.1 字段契约

`POST /api/chat` 与 `POST /api/chat/stream` 中的 `reply` 字段：

* **一律是已净化的纯文本**：不含 `**`、`__`、`~~`、反引号、行首 `# ` / `> ` / `- `，
  不含 Markdown 表格分隔行，不含 `{"reply": …}` / ```` ```json ```` 外壳；
* 换行保留（气泡是 `pre-wrap`，多段之间用空行分隔看起来最自然）；
* 纯文本输入**逐字符不改**（既有的精确字符串断言依赖这一点）。

`/api/chat/stream` 的 SSE 事件形状不变，前端与测试依赖它们：

```text
{"type":"plan",      "plan":[{"agent","task"},...], "router":"llm|rule"}
{"type":"task_start","index":0,"total":2,"agent":"R1","task":"..."}
{"type":"token",     "index":0,"content":"已净化的片段"}
{"type":"task_done", "index":0,"total":2,"agent":"R1","result":{...}}
{"type":"done",      "result":{...}}          # 用于落库
{"type":"error",     "error":"..."}
```

### 3.2 前端职责

* 聊天气泡**只做纯文本渲染**（`textContent` + `white-space: pre-wrap`）；
* **不要再引入 Markdown 渲染器**（`marked` / `markdown-it` / `DOMPurify` 之类）：
  一是服务端已保证纯文本，二是引入 `innerHTML` 渲染会带来 XSS 面；
* 前端**不要**对流式 `token` 做二次过滤：净化器是有状态的（要跨 chunk 持有
  「可能是半截标记」的尾巴），两层状态机叠加会拆碎标记或吞字。

---

## 4. 实现要点

### 4.1 净化器不变量（可直接依赖）

* **永不抛异常**：非字符串原样返回，内部整体 `try/except` 兜底；
* **幂等**：`sanitize_reply(sanitize_reply(x)) == sanitize_reply(x)`，因此多处重复
  净化是安全的（这也是「安全网」敢到处加的前提）；
* **纯文本零改动**：输入不含任何 Markdown / JSON 特征时逐字符原样返回。

### 4.2 为什么流式与一次性净化结果可能不完全逐字一致

流式阶段拿不到「整条回复」，只能做保守清洗：JSON 解包只在 `ReplyStreamFilter.flush()`
里做；半截标记要先留在缓冲区。因此：

* `feed(...)` 各片段 + `flush()` 拼接后的文本，与 `sanitize_reply(整条原文)`
  **可能在空白、极端嵌套标记上不完全逐字一致**；
* 但两者都满足「不含 Markdown 标记」这条硬要求；
* 落库/最终气泡用的是 `done` 事件里的 `sanitize_reply` 结果，以它为准。

---

## 5. 新增 Agent 的接入步骤（两行改动）

任何新的子 Agent，只要其 `chat()` 的返回值会进聊天气泡，就必须做：

```python
# 1) 文件顶部 import（相对导入按既有字母序插入）
from .text_format import sanitize_reply

# 2) 组装返回值时把 reply 包一层（多段文本分别包）
return {"reply": sanitize_reply(final_text), ...}
```

补充：

* 有异常 / 审核拦截 / 兜底文案的分支同样要包（凡是「用户会看到」的字符串）；
* 若该 Agent 提供 `chat_stream()`，**不要**自己在里面过滤 Markdown：supervisor 会为
  每个子任务挂一个 `ReplyStreamFilter`；只要保证 `token` 事件的 `content` 是模型原文即可；
* `trace` / `tasks` / `plan` 等结构化字段不要净化，它们不是给气泡渲染的。

---

## 6. 已知边界

1. **纯文本逐字符不变**：净化器只在检测到 Markdown / JSON 特征时才动文本，
   行尾空格、多余空行等一律保留（既有测试依赖精确断言）。
2. **幂等**：重复净化不会二次变形，因此可以在多层重复加安全网。
3. **净化器永不抛异常**：任何内部异常都被吞掉并返回原文本，调用方无需 `try`；
   代价是「净化失败」表现为「原样输出」，不会阻断对话链路。
4. **流式 ≠ 一次性**：见 §4.2，二者可能不完全逐字一致，但都不含标记。
5. **语义层面不保证**：净化只处理「标记噪声」，不判断内容对错、不重写措辞；
   模型把答案写成表格时，表格会退化成「空格分隔的行」，信息仍在但可读性有限——
   这属于提示词层的职责（`OUTPUT_STYLE_RULE`）。
