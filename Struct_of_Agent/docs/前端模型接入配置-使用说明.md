# 前端模型接入配置 · 使用说明

> 目标：**不用改环境变量、不用重启服务**，在页面上手填 Base URL、API Key 与模型名，
> 测试连接后点「保存并启用」即时生效。

## 1. 快速上手

```powershell
# 1) 启动本地测试服务（在项目根目录执行）
D:\Bank-Agent\.venv\Scripts\python.exe Struct_of_Agent\web_test\server.py
#    或：cd Struct_of_Agent; ..\.venv\Scripts\python.exe -m uvicorn web_test.server:app --reload
```

2. 浏览器打开 <http://127.0.0.1:8000>，点击右上角**齿轮按钮**。
3. 在「模型接入」区域按顺序填：
   - **Base URL**：从你的服务商文档里复制接口前缀，直接粘进输入框（如
     `https://api.deepseek.com/v1`）。页面**没有供应商下拉**，一切手填；
   - **API Key**：粘贴你的 Key（输入框默认打码，可点「显示」核对）；
   - **模型名**：填服务商文档里的模型标识（如 `deepseek-chat`）；
   - （可选）**响应格式**：默认 `文本（推荐）` 就行，只有需要模型稳定输出 JSON 时才改；
   - （可选）**超时（秒）**：**留空即可**（留空就用默认 `120` 秒，输入框里的灰色 `120`
     只是占位提示），网络慢或模型排队时再手动填大一点（最大 `300`）；
   - 点 **测试连接** → 看到「连接成功：模型 xxx 响应正常，耗时 N ms」；
   - 点 **保存并启用** → 顶栏徽标变成 `模型模式 · 你的模型名`，此后对话就走这个模型。

> 想接自建网关或本地模型？照样直接手填 Base URL（如 `http://127.0.0.1:11434/v1`）
> 与模型名即可，不需要先在下拉里选「自定义」。

## 2. 界面上都有什么

| 区域 | 字段 | 说明 |
| --- | --- | --- |
| 模型接入 | Base URL | **手填**，从服务商文档复制接口前缀；只填域名时后端自动补 `/v1` |
| | API Key | 密码框；已配置过时留空表示**沿用**原来的 Key |
| | 模型名 | 手填服务商文档里的模型标识 |
| | 响应格式 | 三选一：`文本（推荐）`（默认）/ `JSON 对象` / `JSON Schema`；日常对话保持默认即可 |
| | 超时（秒） | **可留空**（留空 = 后端默认 `120` 秒），范围 `1 ~ 300`；与「响应格式」同一行常显 |
| | 状态标签 | 弹窗头部：`模型模式 · <模型名>` / `环境变量模式 · <模型名>` / `未配置模型`；顶栏与气泡：`模型模式` / `环境变量模式` / `Mock 离线模式` |
| 联网搜索接入（可选） | 接口地址 / API Key / 返回条数 / 超时 | **默认折叠**的可选区块；用于天气、汇率、新闻等实时问题。**不配置也不影响转账（R1）与账单分析（R2）**，只是没有实时联网结果 |

三个按钮的作用：

- **测试连接** —— 只探测、**不改变**当前生效配置；
- **保存并启用** —— 先探测，**探测通过才替换**；探测失败时当前配置原样保留；
- **清除配置** —— 清掉页面配置，回落到环境变量；若也没有环境变量则进入 Mock 离线模式。

> 弹窗底部**只有这三个按钮**。联网搜索自己的「清除搜索配置 / 测试搜索连接 / 保存搜索配置」
> 在折叠区块内部，不会被误当成必填项。

### 2.1 响应格式怎么选（大白话版）

「响应格式」只影响**怎么让模型开口**，不影响接哪家模型，也不影响转账、账单分析能不能用。

| 选项 | 发给模型的东西 | 含义 | 什么时候用 |
| --- | --- | --- | --- |
| `文本（推荐）`（`text`） | 什么也不额外发 | 模型自由输出自然语言 | **默认值，日常都选它** |
| `JSON 对象`（`json_object`） | `{"type": "json_object"}` | 要求模型只吐一个合法 JSON 对象 | 你自己的脚本要拿结构化结果时 |
| `JSON Schema`（`json_schema`） | 一个**宽松** schema（`{"type": "object", "additionalProperties": true}`） | 要求模型吐一个 JSON 对象，字段不限 | 同上，且希望显式声明「要对象」时 |

- **为什么默认是「文本」？** 这个银行 Agent 干活靠的是**工具调用**（转账、查账单都是调工具完成的），
  最终给人看的回复本来就是自然语言。硬让模型输出 JSON，容易把该说的说明塞进 JSON 字符串里，
  甚至和工具调用契约互相打架。所以页面对话**请保持「文本（推荐）」**。
- `json_object` / `json_schema` 是给「下游程序要解析」的场景准备的。注意本项目用的
  `json_schema` 是**刻意宽松**的（只保证是个 JSON 对象，不校验具体字段），需要严格字段约束时
  请自己在调用方再校验一遍。
- 这三个值之外的任何写法，接口会直接返回 422 `LLM_CONFIG_INVALID`，提示
  `响应格式只支持 text / json_object / json_schema`。页面下拉只有这三个合法值，正常点选不会遇到。
- 「测试连接」和「保存并启用」都会带上你选的响应格式与超时。

## 3. 三种模式分别是什么意思

| 顶栏徽标 | 含义 | 什么时候出现 |
| --- | --- | --- |
| `模型模式 · <模型名>` | 正在用页面配置的模型 | 你点过「保存并启用」 |
| `环境变量模式 · <模型名>` | 正在用环境变量里的模型 | 没在页面配置，但存在 `Deepseek_API` |
| `Mock 离线模式` | 固定话术的离线兜底 | 页面和环境变量都没有配置 |

优先级：**页面配置 > 环境变量 > Mock 兜底**。

## 4. Base URL 怎么填

页面**没有任何供应商下拉**，Base URL 需要你从服务商文档里复制后**手填**。
各家的接口前缀不一样，**不要一律补 `/v1`**；下表是常用的**手填参考值**
（这些地址与 v1 版本一致，未做改动）：

| 供应商 | Base URL |
| --- | --- |
| DeepSeek 官方 | `https://api.deepseek.com/v1` |
| [OI] 官方 | `https://api.openai.com/v1` |
| 阿里云百炼 / 通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 月之暗面 Kimi | `https://api.moonshot.cn/v1` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` |
| 火山方舟 / 豆包 | `https://ark.cn-beijing.volces.com/api/v3` |
| 百度千帆 | `https://qianfan.baidubce.com/v2` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| Ollama 本地 | `http://127.0.0.1:11434/v1` |
| vLLM 本地 | `http://127.0.0.1:8000/v1` |

后端的处理规则：

1. 必须是 `http://` 或 `https://` 开头的完整地址；
2. 去掉首尾空白与结尾 `/`；
3. **路径为空时才补 `/v1`**；已有路径（如 `/compatible-mode/v1`、`/api/paas/v4`）原样保留；
4. 不接受带 `?查询参数` 或 `#片段` 的地址（避免把完整端点粘进 Base URL）；
5. 规范化是幂等的：`f(f(x)) == f(x)`。

## 5. 密钥安全

- 密钥**只存在服务进程内存**，不落盘、不写日志、不写浏览器存储；
- 所有接口只返回掩码（形如 `sk-...1234`），长度不足 8 位时全部打码；
- 页面把「Base URL / 模型名 / 响应格式」记在 `localStorage`（键名 `bank_agent.llm.pref`）
  便于下次预填，**唯独不记 Key**；
- **错误信息也会擦除密钥**：部分网关会在报错时回显收到的 Key，而错误文本会出现在
  回复和 `trace` 里，因此所有面向前端的错误文本都先擦除密钥、再截断（顺序不能反，
  否则截断点落在 Key 中间时会残留前缀）；
- **Base URL 不允许内嵌凭据**：`https://user:pass@host` 会被拒绝（这类地址会随
  `base_url` 回传前端并写入本地偏好，属于泄漏面），请用 API Key 字段；
- 进程重启后页面配置即失效，需要重新填写（这是刻意的取舍：不落盘）。

> 想让配置在重启后依然生效，用环境变量方式（见 `requirements.txt` 顶部注释），
> 或后续接入配置中心 / 密钥管理服务。

## 6. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `[LLM_AUTH_FAILED]` 鉴权失败 | Key 无效、过期，或没有该模型的权限；核对 Key 与控制台开通情况 |
| `[LLM_MODEL_NOT_FOUND]` 接口或模型不存在 | Base URL 路径写错（漏了 `/v1` 或多写了 `/chat/completions`），或模型名不对 |
| `[LLM_CONNECTION_FAILED]` 无法连接 | 域名/端口不可达；本地模型确认服务已启动；公司网络可能需代理 |
| `[LLM_TIMEOUT]` 请求超时 | 网络慢或模型排队；在「超时（秒）」里填一个更大的值（留空即默认 120，最大 300），再「测试连接」。**超时与 Base URL / API Key / 模型名无关**，不要去改这三项 |
| `[LLM_RATE_LIMITED]` 触发限流 | 请求过频或额度不足，稍后再试 |
| `[LLM_KEY_REQUIRED]` 请填写 API Key | 既没填 Key，也没有可沿用的 Key |
| `[LLM_CONFIG_INVALID]` + 提示「不要内嵌用户名或密码」 | Base URL 里粘了 `user:pass@`，请改用 API Key 字段 |
| `[LLM_CONFIG_INVALID]` + 提示「响应格式只支持 text / json_object / json_schema」 | 响应格式传了三个合法值之外的内容。页面下拉只有这三个选项，正常点选不会遇到；用 curl 时请传 `text` / `json_object` / `json_schema`，或直接省略该字段（按 `text` 处理） |
| `[LLM_CONFIG_INVALID]` + 提示字段名 | 请求体缺字段或类型不对；页面正常使用不会遇到，用 curl 时请对齐契约 |
| `[SEARCH_CONFIG_INVALID]` 请填写搜索接口地址 | 搜索地址为空。**不会**静默回落到 Tavily，避免把 Key 误发到第三方 |
| 没配联网搜索会怎样？ | **不阻塞转账（R1）与账单分析（R2）**，通用问答也照常回答，只是没有实时联网结果：搜索工具会返回「未配置联网搜索服务：请在页面「模型设置 · 联网搜索」填写接口地址与 API Key，或设置环境变量 Tavily_API」。想用天气/汇率/新闻这类实时问题时，再展开「联网搜索接入（可选）」去配 |
| 对话回复里出现「模型调用失败…」 | 先看冒号后的错误码：`Request timed out.` 属**上游慢**，把「超时（秒）」调大后重发即可，与 Base URL / API Key / 模型名无关；其它情况再重新「测试连接」确认后再保存 |

## 7. 开发者接口速查

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/settings/llm` | 读取模型配置快照（含 `response_format`） |
| `POST` | `/api/settings/llm/test` | 测试连接（**HTTP 恒为 200**，由 `ok` 字段表达结果） |
| `PUT` | `/api/settings/llm` | 保存并启用 |
| `DELETE` | `/api/settings/llm` | 清除运行时配置 |
| `GET/PUT/DELETE` | `/api/settings/search` | 联网搜索配置（**可选**，另有 `POST /api/settings/search/test`） |
| `GET` | `/health/live` | 存活探针 + 当前 `model_mode` / `model` / `base_url`（**非统一响应包**） |

> v2 起 `GET /api/settings/llm/presets` 已被删除，访问返回 **404**；
> 请求体里也不再需要温度 / 最大 token 数。

> 请求体校验失败（缺字段、类型不对）也返回统一响应包，不会看到 FastAPI 默认的
> `{"detail": [...]}`。

完整字段、错误码与状态码见 [前端模型接入配置-契约.md](前端模型接入配置-契约.md)；
各家 Base URL / 模型名的核实来源见 [供应商接入预置调研.md](供应商接入预置调研.md)
（预置功能已在 v2 移除，该文档仅作**手填参考**保留）。

### curl 示例

```bash
# 测试连接
curl -X POST http://127.0.0.1:8000/api/settings/llm/test \
  -H "Content-Type: application/json" \
  -d '{"base_url":"https://api.deepseek.com/v1","api_key":"sk-xxx","model":"deepseek-chat","response_format":"text","timeout":120}'

# 保存并启用
curl -X PUT http://127.0.0.1:8000/api/settings/llm \
  -H "Content-Type: application/json" \
  -d '{"base_url":"https://api.deepseek.com/v1","api_key":"sk-xxx","model":"deepseek-chat","response_format":"text","timeout":120}'

# 查看当前配置（密钥为掩码）
curl http://127.0.0.1:8000/api/settings/llm
```

## 9. 架构速览（改代码前先看这里）

```
页面 web_test/index.html
   │  fetch /api/settings/llm|search   fetch /api/chat
   ▼
web_test/server.py  ──────────────►  supervisor.SupervisorAgent
   │  读写单例                          │  路由到 R1 / R2 / common
   ▼                                    ▼
common/model_manager.py            R1.agent / R2.agent / common.agent
   ModelConfigManager                 │  注入 RuntimeChatModel（委托代理）
   SearchConfigManager                ▼
   RuntimeChatModel ─────────────► common/llm.py  DeepSeekChat（[OI] SDK）
   ▲                                    │
   └── common/runtime_config.py         └── 任意 [OI] 兼容 Base URL
       校验 / URL 规范化 / 掩码 / 响应格式白名单
```

关键设计：

- **热切换**：Agent 构造时注入的是 `RuntimeChatModel` 委托代理，**每次 `chat` 才解析**
  当前生效模型，所以已编译的 LangGraph 图**无需重建**。
- **一致读**：`ModelConfigManager.state()` 在一次加锁内返回「配置 + 模式 + 来源」，
  `snapshot()` 与 `trace_info()` 都走它，避免并发切换时出现
  「模式是 mock 却还带着旧模型名」这类撕裂（前端徽标会错乱）。
- **惰性单例**：Agent 持有的是「获取管理器的函数」而非实例，避免导入期绑定陈旧引用。
- **失败不覆盖**：`configure` 先探测，成功才写入；失败时当前配置分毫不动。
- **异常收敛**：模型不可用时，`SupervisorAgent` 把异常转成一条可读回复
  （`trace.failed = true`），页面不会看到 500 堆栈。
- **先擦后截**：`describe_error(error, secrets)` 先在完整文本上擦除密钥再截断
  （反过来会残留密钥前缀）。
