# 供应商接入预置调研（OpenAI 兼容 / Chat Completions）

> [!NOTE]
> **本文档描述的「预置供应商」功能已在契约 v2 中移除**：页面不再有供应商下拉，
> `common/runtime_config.py` 里的 `PROVIDER_PRESETS` 表、`ModelConfigManager.presets()`
> 与 `GET /api/settings/llm/presets` 接口都已删除（该路径现为 404）。
> 现在页面只接受用户**手填的 Base URL** 与模型名。
>
> 本文档**保留下来仅作参考**：下面各家的 **Base URL 与模型名取值**依然是手填时最有用的
> 对照表（页面「Base URL」输入框就靠它）。阅读时请忽略所有关于「下拉预置」「自动带出」
> 「切换供应商」的交互描述 —— 那些行为在 v2 已不存在。

> 面向「银行智能 Agent」项目的前端「手填 Base URL 与模型名」需求（v1 时期为
> 「选择预置供应商 → 自动带出 Base URL 与默认模型」）。文中出现的
> `id` / `label` / `base_url` / `models` / `default_model` / `requires_key` / `docs_url` / `note`
> 字段结构属于 **v1 契约第 7 节**，该节已在 v2 删除，此处仅作历史参考。
>
> **核实方式**：全部通过 `web_fetch` 直连各家官方文档页面逐条查证，来源 URL 标注在每行末尾。
> 少数站点（火山方舟、百度千帆）正文由 JS 渲染、OpenAI 官网被 Cloudflare 拦截、GitHub 在本环境
> 不可达，这些条目已**显式标注「待核实」**，未标注的即为官方文档原文核实。

**三条最容易踩的坑**：

1. **并非所有供应商都是 `/v1`**：百炼是 `/compatible-mode/v1`，智谱是 `/api/paas/v4`，火山方舟是
   `/api/v3`，千帆是 `/v2`，OpenRouter 是 `/api/v1`。后端**不能**一律「补 `/v1`」或「把路径裁掉换成 `/v1`」。
2. **补全逻辑必须区分「域名根路径」和「已有路径前缀」**：只有路径为空或为 `/` 时才补，已有路径一律保留。
3. **本地部署不是「不需要 Key」，而是「需要但被忽略」**：Ollama 官方示例明确写
   `api_key='ollama', # required but ignored`，OpenAI SDK 要求 `api_key` 非空，否则构造客户端即报错。

### B.1 ChatGPT-Next-Web / NextChat

- 仓库：<https://github.com/ChatGPTNextWeb/NextChat>

- 做法：内置「模型服务商」下拉（OpenAI / Azure / 各类兼容端点），选「自定义」时暴露
  **Custom Endpoint** 输入框；配置（含 endpoint、模型名、temperature 等）整体序列化进浏览器
  `localStorage`，API Key 也随配置一起存在前端，**纯浏览器侧、无后端代理**。

- 可借鉴：
  1. **默认值直接写成完整的 `https://api.openai.com/v1`** —— 印证「预置 base_url 必须是可直接传给
     SDK 的完整地址」这一要求。
  2. **环境变量与页面配置双入口、页面优先** —— 与本项目契约第 2 节 `mode` 的
     `model`（页面配置）/ `env`（环境变量）优先级设计一致。
  3. 配置存服务端、不落浏览器，安全性优于 NextChat 的 `localStorage` 方案；本项目契约第 7 节
     「密钥绝不落盘 + 绝不回传明文」是更彻底的取舍。

### B.6 横向对比：配置持久化与安全取舍

| 项目 | 密钥存放位置 | 安全取舍 |
| --- | --- | --- |
| NextChat | 浏览器 `localStorage` | 零后端、部署最简；但 XSS 即可窃取密钥 |
| LobeChat | 服务端数据库（可自托管） | 支持多用户共享；需自行加固数据库 |
| Dify | 服务端数据库，仅 owner/admin 可管 | 权限模型清晰，凭据工作区内共享 |
| one-api / new-api | 服务端数据库 | 集中管控多 Key，适合团队/网关场景 |
| Open WebUI | 服务端数据库 + 环境变量 | 管理员后台统一配置 |
| **本项目（契约）** | **进程内存，绝不落盘** | 最严格：重启即失效，换来零泄漏面 |

**结论**：本项目契约选的是「**内存态 + 只回传掩码 + 失败不覆盖**」的最严方案，比上述开源项目都保守；
可借鉴的是它们的**交互形态**（独立测试连接、保存前校验），而不是它们的**持久化策略**；
其中「预设下拉」这一条本项目已在 v2 放弃。

## D. Base URL 规范化规则建议

后端在把用户手填的 `base_url` 交给 OpenAI SDK 之前，应按下面的顺序做规范化。**核心原则：
「只补不裁」——可以补全缺失的路径，但绝不擅自改写用户已经写好的路径。**

### D.1 规则清单（按执行顺序）

| # | 规则 | 动作 | 理由 |
| --- | --- | --- | --- |
| 1 | **去首尾空白** | `s.strip()` | 用户从文档复制时极易带上空格/换行/全角空格 |
| 2 | **拒绝非 http(s)** | 协议不是 `http`/`https` → `LLM_CONFIG_INVALID` | 只允许 http(s)，挡掉 `ftp://`、`file://`、`javascript:`、无协议裸串 |
| 3 | **拒绝带 query / fragment** | 出现 `?` 或 `#` → `LLM_CONFIG_INVALID` | Base URL 是路径前缀，query/fragment 无意义，且会污染 SDK 拼接出的 `/chat/completions` |
| 4 | **拒绝内嵌用户名密码** | `user:pass@host` → `LLM_CONFIG_INVALID` | 凭据只能走 `api_key`，塞进 URL 会进日志/报错信息，违反契约第 7 节 |
| 5 | **归一化主机名** | 主机名转小写；`127.0.0.1` 与 `localhost` 按需统一 | 避免同义不同写法造成「配置没变但被判定为变更」 |
| 6 | **去尾部 `/`（保留根路径语义）** | 反复去掉末尾 `/`，但至少保留一个根 `/` | `https://api.deepseek.com/v1/` 与 `.../v1` 等价，统一形态便于比较与去重 |
| 7 | **只在「路径为空或为 `/`」时补 `/v1`** | `path in ("", "/")` → 追加 `/v1` | 契约第 6.1 节原文要求。`https://api.deepseek.com` → `https://api.deepseek.com/v1` |
| 8 | **已有路径一律原样保留** | `path` 非空且非 `/` → 不动 | **关键**：百炼 `/compatible-mode/v1`、智谱 `/api/paas/v4`、火山方舟 `/api/v3`、千帆 `/v2`、OpenRouter `/api/v1` 都不是 `/v1`，一旦改写全部 404 |
| 9 | **不做自动 `https` 升级** | 保持用户给的协议 | 本地部署（Ollama/vLLM）大量使用 `http://`，强制升级会直接连不上 |
| 10 | **拒绝非 http(s) 之外的畸形输入** | 如 `http://`、`https://`（无 host）→ `LLM_CONFIG_INVALID` | 空 host 无意义，早失败早报错 |
| 11 | **长度上限** | 建议 `<= 2048` | 防御性上限，避免超长串进日志 |

### D.2 参考实现（伪代码）

```python
from urllib.parse import urlsplit, urlunsplit

def normalize_base_url(raw: str) -> str:
    s = (raw or "").strip()
    if not s:
        raise ValueError("base_url 不能为空")

    parts = urlsplit(s)

    # 规则 2：只允许 http / https
    if parts.scheme not in ("http", "https"):
        raise ValueError("base_url 必须以 http:// 或 https:// 开头")
    # 规则 10：必须有主机名
    if not parts.hostname:
        raise ValueError("base_url 缺少主机名")
    # 规则 3：不允许 query / fragment
    if parts.query or parts.fragment:
        raise ValueError("base_url 不允许带查询参数或锚点")
    # 规则 4：不允许内嵌用户名密码
    if parts.username or parts.password:
        raise ValueError("base_url 不允许内嵌用户名密码，请使用 API Key 字段")
    # 规则 11：长度上限
    if len(s) > 2048:
        raise ValueError("base_url 过长")

    # 规则 5：主机名小写
    host = parts.hostname.lower()
    netloc = host if parts.port is None else f"{host}:{parts.port}"

    # 规则 6：去掉尾部多余的 '/'
    path = parts.path.rstrip("/")

    # 规则 7 / 8：只在路径为空时补 /v1；已有路径原样保留
    if not path:
        path = "/v1"

    # 规则 9：保持原协议，不强制 https
    return urlunsplit((parts.scheme, netloc, path, "", ""))
```

### D.3 为什么这么设计

1. **「只补不裁」是安全性的前提。** 供应商的路径前缀五花八门（`/compatible-mode/v1`、
   `/api/paas/v4`、`/api/v3`、`/v2`、`/api/v1`），任何「统一成 `/v1`」的启发式都会误伤。
   宁可让用户填错后由「测试连接」报 404（`LLM_MODEL_NOT_FOUND` 或 `LLM_CONNECTION_FAILED`），
   也不要后端悄悄改掉一个正确的地址。
2. **规范化必须是幂等的。** `normalize(normalize(x)) == normalize(x)`，否则「保存 → 读取 → 再保存」
   会把地址越改越离谱。上面 11 条规则全部满足幂等。
3. **拒绝 query/fragment 是为了拼接安全。** SDK 内部是 `base_url + "/chat/completions"`，
   若 base_url 带 `?key=...`，拼出来的 URL 会变成 `...?key=.../chat/completions`，报错信息难以理解。
4. **不做 https 强制升级是为了本地部署。** Ollama（`http://127.0.0.1:11434/v1`）、
   vLLM（`http://127.0.0.1:8000/v1`）、LM Studio（`http://127.0.0.1:1234/v1`）都是明文 http，
   强制升级等于直接废掉这三个预置项。
5. **与契约一致性。** 规则 6/7/8 逐字对应契约第 6.1 节：「若路径为空或为 `/`，后端自动补 `/v1`；
   已带路径（如 `/v1`、`/openai/v1`）则保留并去掉尾部 `/`」。本节的建议是把它**扩写成可测试的规则表**，
   并补充了 query/fragment、内嵌凭据、协议白名单等契约未显式列出的边界。
6. **搜索配置不复用这套规则。** 契约第 6.2 节明确 Tavily 的 `base_url` 是**完整端点地址**
   （`https://api.tavily.com/search`），**不做 `/v1` 补全**。两套规范化函数必须分开，不要共用一个。
