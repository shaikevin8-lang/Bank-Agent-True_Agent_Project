# 登录 / 注册功能 —— 冻结契约（前后端共同遵守）

> 本文件是本次改造的**唯一事实来源**。后端、前端、文档三个子任务都以它为准，任何一方不得单方面改动字段名、错误码、DOM id。

## 0. 需求（用户原话要点）

1. 启动本项目后，**首先**看到登录页面；
2. 已有账号：输入账号名 + 密码 → 进入主页面（聊天界面）；
3. 未注册：先注册，注册只需 **账号名 + 密码 + 确认密码** 即可创建账号；
4. 注册成功后回到登录处，用新账号登录进入主页面。

不做（明确排除，避免范围蔓延）：找回密码、验证码、第三方登录、多角色权限、按用户隔离历史会话、限流与锁定、服务端对 `/api/chat` 等接口强制鉴权（页面层门禁 + 会话接口鉴权面另行演进）。

## 2. 口令与令牌

- 口令哈希：`hashlib.pbkdf2_hmac("sha256", password.encode("utf-8"), salt, iterations)`，`iterations = 200_000`，`salt = os.urandom(16)`，哈希与盐都以十六进制字符串入库。
- 校验用 `hmac.compare_digest`。
- 令牌：`secrets.token_urlsafe(32)`；库里只存 `hashlib.sha256(token.encode()).hexdigest()`。
- 会话有效期：`SESSION_TTL_DAYS = 7`（固定过期，不做滑动续期；登录时刷新 `last_login_at`）。
- Cookie 名固定 `bank_agent_session`；属性：`httponly=True, samesite="lax", path="/", max_age=7*24*3600`；`secure=False`（本地 http）。

## 3. 账号名 / 密码规则（前后端必须一致）

- 账号名：`strip()` 后长度 3–32；不允许空格、制表符、换行等空白与控制字符；其余字符（中英文、数字、`_ . -` 等）允许；唯一性按 `lower()` 判定。
- 密码：长度 6–64，**不做 strip**（前后空格是密码的一部分），不允许纯空白。

错误码与文案（后端返回的 `message` 直接给用户看）：

| 错误码 | HTTP | message |
| --- | --- | --- |
| AUTH_USERNAME_INVALID | 422 | 账号名需为 3–32 个字符，且不能包含空格 |
| AUTH_PASSWORD_INVALID | 422 | 密码长度需为 6–64 个字符 |
| AUTH_PASSWORD_MISMATCH | 422 | 两次输入的密码不一致 |
| AUTH_USERNAME_TAKEN | 409 | 该账号名已被注册，请换一个 |
| AUTH_USERNAME_REQUIRED | 422 | 请输入账号名 |
| AUTH_PASSWORD_REQUIRED | 422 | 请输入密码 |
| AUTH_BAD_CREDENTIALS | 401 | 账号名或密码不正确 |
| AUTH_USER_DISABLED | 403 | 该账号已被停用 |
| AUTH_UNAUTHORIZED | 401 | 登录状态已失效，请重新登录 |
| AUTH_SCHEMA_MISSING | 503 | 账号数据表尚未创建，请先执行 python scripts/db.py upgrade |
| AUTH_UNAVAILABLE | 503 | 账号服务暂不可用，请确认数据库已启动后重试 |

## 4. HTTP 接口（统一响应包 `{ok, message, error_code, data}`）

全部挂在 `/api/auth` 前缀，`APIRouter(prefix="/api/auth", tags=["auth"])`，用 `api_common.ok` / `api_common.fail`。

### POST /api/auth/register

请求：`{"username": "alice", "password": "secret123", "confirm_password": "secret123"}`

- 201 → `ok("注册成功，请使用该账号登录", {"user": {"username": "alice", "created_at": "<ISO8601>"}})`
- 422 / 409 / 503 见上表。
- 注册**不**自动登录、不下发 cookie。

### POST /api/auth/login

请求：`{"username": "alice", "password": "secret123"}`

- 200 → `ok("登录成功", {"user": {"username": "alice", "created_at": "<ISO>", "last_login_at": "<ISO>"}, "expires_at": "<ISO>"})`，同时 `Set-Cookie: bank_agent_session=<token>; Path=/; HttpOnly; SameSite=lax; Max-Age=604800`。
- 401 `AUTH_BAD_CREDENTIALS`（账号不存在与密码错误返回**完全相同**的响应，避免账号枚举）。
- 403 `AUTH_USER_DISABLED`；422 空账号/空密码；503 见上表。

### POST /api/auth/logout

- 200 → `ok("已退出登录", {"logged_out": true})`，并 `delete_cookie("bank_agent_session", path="/")`。
- 无 token / token 无效也返回 200（幂等）。

### GET /api/auth/me

- 已登录 200 → `ok("", {"authenticated": true, "user": {"username", "created_at", "last_login_at"}, "expires_at": "<ISO>"})`
- 未登录/过期/已注销 401 → `fail("登录状态已失效，请重新登录", "AUTH_UNAUTHORIZED", 401)`

令牌读取顺序：Cookie `bank_agent_session` → 请求头 `Authorization: Bearer <token>`（便于 curl 调试）。

## 5. 前端（Struct_of_Agent/web_test/index.html，单文件、零外部依赖）

### 5.1 DOM 契约（id 不可改名）

```
#authGate               全屏登录/注册遮罩（未登录时可见）
  #authForm             <form>，回车即提交
    #authTabLogin       登录页签（默认 active）
    #authTabRegister    注册页签
    #authUsername       账号名
    #authPassword       密码
    #authConfirmField   确认密码外层容器（登录模式下 hidden）
    #authConfirmPassword 确认密码
    #authError          role="alert" 错误提示（默认 hidden）
    #authSubmit         提交按钮
    #authHint           辅助文案
#authUser               顶栏显示当前账号名
#logoutBtn              顶栏「退出登录」
```

`#app` 在未登录时带 `hidden` 属性；必须补 CSS `.app[hidden]{display:none}`（否则 `.app{display:flex}` 会盖掉 UA 的 `[hidden]` 规则）。

### 5.2 启动流程

页面脚本末尾把原来直接执行的三步启动（`initSessions()` IIFE、`refreshModeBadge()`、`initClockAndHitl()`）收进 `startApp(user)`，改为：

```
bootstrapAuth()
  → fetch('/api/auth/me', {credentials:'same-origin', headers: apiHeaders(false)})
     · 200 且 body.ok → setSessionUser(data.user) → startApp()
     · 其它（401/网络失败）→ showAuthGate('login')
```

- `startApp()` 只能用 `started` 标志保证执行一次；`currentOperator` 取自登录用户（顶栏 `#authUser` 显示账号名）。
- `showAuthGate(mode)`：显示 `#authGate`、隐藏 `#app`、清空错误、`#authUsername` 聚焦、按 mode 切换页签与 `#authConfirmField` 可见性。
- 登录成功：`startApp()`；失败：把 `message` 显示在 `#authError`（401 即「账号名或密码不正确」）。
- 注册成功：切到登录页签、预填账号名、清空两个密码框、`#authHint` 显示「注册成功，请使用该账号登录」。
- 提交中：`#authSubmit` 加 `disabled`，文案变「登录中…」/「注册中…」，结束后恢复。
- 退出登录：`POST /api/auth/logout` → 清空聊天区 DOM 与内存态（`currentSessionId` 等）→ `showAuthGate('login')`。
- 前端提交前做与第 3 节一致的本地校验（非空、长度、两次一致），校验不过不发请求。
- 所有请求走已有 `fetch` 封装风格并带超时；`credentials: 'same-origin'` 必须显式带上。
- 样式用现有 CSS 变量（`--brand`、`--radius`、`--line`、`--surface` 等），居中卡片、移动端自适应、不引入外部字体/图标。

### 5.3 既有前端测试

`tests/frontend/test_sidebar.mjs`、`tests/frontend/test_settings_panel.mjs` 的 `stubFetch` 遇到未打桩请求会 `throw`，必须新增分支：
