## 1. 目标（可演示、可测试、可审计）

### 1.1 演示时钟（Demo Clock）
让所有「按时间触发」的能力（R1 定时转账、R6 定时/生日任务、R5 续费提醒）在演示中**不需要等真实时间**：

1. 全局唯一的**业务时钟**抽象：业务时间 = 真实时间 + 偏移（可冻结）。
2. 推进时间后**立即结算到期任务**（catch-up），而不是等下一次真实轮询。
3. 时钟状态**持久化**（重启后位置不丢，ADR-003 定语义）。
4. 每次变更写**审计**，且业务记录同时保存 `real_at` / `business_at` 两个时间。
5. 前端顶栏有业务时间徽标 + 推进/冻结/重置面板，对话流插入系统提示。

### 1.2 人工介入中断（HITL Interrupt）
让「必须真人决定」的节点**真正中断图执行**，落一条可认领、可审批、可超时、可审计的**人工案件**，处理后**恢复执行**：

1. 触发场景（`reason_code`）：`high_risk_write`（高风险写操作/超额度）、`unknown_result`（工具结果未知）、`missing_info`（需人工核验资料）、`policy_conflict`（策略冲突）、`tool_degraded`（外部能力不可用）。
2. 案件状态机：`open → claimed → approved|rejected|info_required`；旁支 `expired` / `cancelled`。
   决策只有三种（对齐 FR-COM-003 与 §8.4「人工审核只提供最小闭环：单案件、通过/拒绝/补件、理由和审计」）：
   `approve`（通过，恢复执行）、`reject`（拒绝，不执行并说明）、`request_info`（补件，案件回到 `open` 并通知用户补充资料）。
3. 认领独占 + 版本号乐观锁（ADR-004 冲突规则）；重复决策幂等；超时按 fail-closed 处理。
4. SLA 倒计时**用业务时钟**（与演示时钟联动：推进时间即触发过期扫描）。
5. 前端：聊天流内嵌「等待人工处理」卡片 + 操作员案件队列面板。

### 1.3 身份与职责分离（对齐需求 §3.3 角色表）

| 角色 | 能力 | 依据 |
| --- | --- | --- |
| `user` 普通用户 | 发起任务、确认自己的任务、查看本人案件状态；**不能**审批自己的案件 | §3.3 |
| `risk_reviewer` 风控审核员 | 认领并处理**分配给自己的单案件**：通过/拒绝/补件 + 必填理由；**不能**代替用户确认、不能操作演示时钟 | §3.3 / FR-COM-003 |
| `ops_admin` 管理员/运营演示 | 管理演示配置（演示时钟推进/冻结/重置）、查看脱敏轨迹与案件；**不能**审批执行 | §3.3 |

实现方式：请求头 `X-Role` + `X-Operator`（缺省视为 `user`）；服务端按上表强制职责分离，
越权返回 `403 role_not_allowed` 并写审计。前端提供「身份切换」下拉，默认 `user`。


## 2. 架构与文件布局（新增为主，尽量少改既有文件）

### 2.1 时钟
```
Struct_of_Agent/common/clock.py            # Clock 协议 + SystemClock + SimClock + get_clock()/use_clock()
Struct_of_Agent/common/clock_store.py      # app.sim_clock 持久化读写（单例行）
Struct_of_Agent/web_test/api_clock.py      # /api/clock/* 路由（APIRouter）
```
- `Clock.now()` → 业务时间（`datetime`，tz-aware，Asia/Shanghai）；`Clock.real_now()` → 真实时间。
- `SimClock` 状态：`enabled: bool`、`offset_seconds: int`、`frozen_at_business: datetime|None`、`version: int`。
  - `enabled=False` → `now()==real_now()`（默认）。
  - `enabled=True` → `now() = frozen_at_business if frozen else real_now()+offset`。
- 全局入口 `common.clock.get_clock()`；进程内单例，状态由 `clock_store` 加载/落库；**禁止**其它模块直接 `datetime.now()` 取业务时间。
- 到期结算入口 `common/clock.run_due(business_now)` → 调用各领域注册的 due-scan 回调（R1/R5/R6 注册，回调签名 `(business_now) -> list[dict]`），返回触发摘要供审计与前端提示。

### 2.2 人工案件
```
Struct_of_Agent/common/hitl.py             # 领域服务：open_case/claim/decide/cancel/expire_sweep/状态机校验
Struct_of_Agent/web_test/api_hitl.py       # /api/hitl/* 路由（APIRouter）
```
- 图中断：在**写操作执行闸门**处判断——`common/hitl.gate(session, task, proposal)` 返回
  `Allow | Interrupt(case)`；`Interrupt` 时调度器把本轮结果标记为「已挂起等待人工处理」并保存 proposal（含工具名+参数+幂等键+图 thread_id），**不执行**副作用。
- 恢复：批准后 `resume` 用存档 proposal 重新走安全门执行（幂等键防重复扣款）；拒绝则生成面向用户的说明。
- 若现有图已有 checkpointer/thread_id，优先用 LangGraph `interrupt()/Command(resume=)`；否则用「proposal 存档 + 重放」实现（两者都必须保留 `graph_thread_id` 字段以便未来切换）。

## 3. 接口契约（后端必须与此一致，前端据此开发）

```
GET  /api/clock                      -> {enabled, business_now, real_now, offset_seconds, frozen, version}
POST /api/clock/advance  {seconds|to, ack:true, operator?} -> {clock:{...}, triggered:[{kind,id,summary}], audit_id}
POST /api/clock/freeze   {ack:true, operator?}             -> {clock:{...}}
POST /api/clock/resume   {ack:true, operator?}             -> {clock:{...}}
POST /api/clock/reset    {ack:true, operator?}             -> {clock:{...}}
（统一响应包沿用项目现有 {ok, message, error_code, data} 约定）

GET  /api/hitl/cases?status=&session_id=&limit=  -> {items:[...], total}
GET  /api/hitl/cases/{case_no}                   -> {case:{...}, events:[...]}
POST /api/hitl/cases/{case_no}/claim   {operator}                     -> {case:{...}}
POST /api/hitl/cases/{case_no}/decision{operator, decision:approve|reject, note?, pin?} -> {case:{...}, resumed:{...}|null}
POST /api/hitl/cases/{case_no}/cancel  {operator, note?}              -> {case:{...}}
POST /api/hitl/sweep                   {now?}                         -> {expired:[case_no]}
```
鉴权与职责分离：请求头 `X-Role: user|risk_reviewer|ops_admin` + `X-Operator: <名字>`（缺省 `user`）。
- `/api/clock/*` 写操作仅 `ops_admin`；`/api/hitl/cases/*/claim|decision` 仅 `risk_reviewer`；`GET` 类读接口 `user` 只能看本人 `session_id` 的案件。
- 决策类写操作必须带 `ack=true` 与非空 `note`（`approve` 也建议填理由，`reject`/`request_info` 必填）；
- 越权 → `403 role_not_allowed`（fail-closed）；一律写 `audit.event` + 领域事件表。
